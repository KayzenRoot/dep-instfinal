## Results

| Case | Audio | Wall time | RTF | Max RSS | CPU |
| --- | ---: | ---: | ---: | ---: | ---: |
| short 1 (3 sentences) | 8.812 s | 1.59 s | 0.180 | 245,296 KB | 161% |
| short 2 | 8.719 s | 1.47 s | 0.169 | 239,004 KB | 164% |
| short 3 | 8.731 s | 1.47 s | 0.168 | 244,052 KB | 165% |
| full 120 s script (232 words) | 81.003 s | 8.86 s | 0.109 | 281,996 KB | 191% |

- The full run used 16.86 s user + 0.09 s system, 191% CPU (effectively both vCPU), so concurrency remains **1**.
- `uv` may have used its normal user cache outside `/tmp`; no service, config, package or file was installed persistently. The benchmark itself and model copy were removed.
- Full output was downloaded and transcribed locally with Vosk small pt: confidence **0.909**, recognizing the 232-word horror script end-to-end.
- Host x64 comparison for the same short text: ~12.39 s and ~531 MB incremental peak, but that includes Python startup + Piper + the full ffmpeg trim/pause/concat pipeline, so it is **not** an apples-to-apples comparison. The valid conclusion is the absolute ARM64 result: 81 s of audio in 8.86 s with 282 MB RSS.

## Decision

**GO** for optional local TTS on the ARM64 worker with concurrency 1. The measured cost is far below the FFmpeg render budget; no GPU/paid API is needed. The TTS remains optional: the manual voice upload and the Piper CLI fallback are unchanged.
